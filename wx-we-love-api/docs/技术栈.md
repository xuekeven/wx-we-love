# TechStack

## 1. 后端技术栈总览

- 运行时：Node.js
- Web 框架：Express
- ORM：Sequelize
- 数据库：
  - 生产：Docker MySQL
  - 本地开发：SQLite 文件库，或按需连接 MySQL
- 认证：JWT（`jsonwebtoken`）
- 文件上传：Multer

## 2. 数据库策略与环境选择

### 开发环境（默认）

- 推荐使用 SQLite 文件库，开箱即用，适合本地调试。
- 典型配置在 `src/config/database.js`，示例：

```js
new Sequelize({
  dialect: 'sqlite',
  storage: './database.sqlite',
  logging: false
})
```

### 生产环境（当前）

- 当前生产环境使用 Docker MySQL。
- 常用容器名：`mysql-server`
- 数据库名：`wx_we_love`
- 后端通过环境变量连接 MySQL：

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=wx_we_love
DB_USER=root
DB_PASSWORD=your_password
```

服务器上查询数据库时，优先使用 Docker 命令：

```bash
docker exec -it mysql-server mysql -u root -p wx_we_love
```

常用查询、备份与恢复命令见：

- [数据库常用命令](./docs/数据库常用命令.md)
- [数据备份](./docs/数据备份.md)

### 启动行为

- 服务启动时会执行 `sequelize.sync()` 创建缺失表。
- 为兼容旧数据，启动时会检查 `Anniversaries.userId` 与 `Menstruals.userId` 字段，不存在时自动补充。
- 生产环境升级前必须先备份数据库；如需严格迁移流程，建议后续引入 migration。

## 3. 数据模型（前端协作视角）

当前核心模型位于 `src/models/`：

- `User`：用户与情侣关系、资料信息、功能排序
- `Anniversary`：纪念日数据
- `Menstrual`：经期记录
- `MoodDiary`：心情日记主体
- `MoodDiaryComment`：心情日记评论

### 常见字段类型对照

| Sequelize | TypeScript 常见映射 | 说明 |
|---|---|---|
| `DataTypes.INTEGER` | `number` | 整数 |
| `DataTypes.STRING` | `string` | 字符串 |
| `DataTypes.TEXT` | `string` | 长文本 |
| `DataTypes.DATEONLY` | `string` | 日期（`YYYY-MM-DD`） |
| `DataTypes.DATE` | `string \| Date` | 日期时间 |
| `DataTypes.BOOLEAN` | `boolean` | 布尔值 |
| `DataTypes.JSON` | `Record<string, unknown>` | JSON 对象 |
| `DataTypes.UUID` | `string` | UUID |

### 协作建议

- 前端以接口返回结构为准，不直接假设数据库字段名永不变化。
- 时间字段统一做格式化（后端返回 ISO 时前端再按 UI 场景渲染）。
- 对可空字段做好兜底（如头像、备注、扩展信息）。

## 4. JWT 与 `JWT_SECRET` 安全基线

### JWT 在项目中的作用

- 登录成功后，后端签发 token。
- 受保护接口通过 `Authorization: Bearer <token>` 校验身份。

### `JWT_SECRET` 的关键原则

- 必须配置，不应使用默认值。
- 建议长度至少 32 位，推荐 64 位随机十六进制。
- 开发/生产环境必须使用不同密钥。
- 不得提交到 Git，不得写死在代码中，不得打印到日志。

### 生成安全密钥（推荐）

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 示例配置

```env
JWT_SECRET=replace_with_your_strong_random_secret
```

### 轮换策略（泄露或怀疑泄露时）

1. 生成新密钥并更新环境变量。
2. 重启后端服务。
3. 旧 token 全部失效，用户需重新登录。
4. 排查异常访问日志。

## 5. 数据操作与调试方式

### 常见 ORM 操作

- 查询：`findAll` / `findOne` / `findByPk`
- 创建：`create`
- 更新：`update`
- 删除：`destroy`

### 调试工具建议

- SQLite / MySQL 可视化：TablePlus、DBeaver
- MySQL 官方：Workbench
- 命令行方式：
  - SQLite：`sqlite3 database.sqlite`
  - Docker MySQL：`docker exec -it mysql-server mysql -u root -p wx_we_love`

## 6. 常见问题速查

- 数据重启后丢失：
  - 检查是否误用了 SQLite 内存库（`:memory:`）。
- 连接 MySQL 失败：
  - 检查 Docker 容器是否运行：`docker ps`。
  - 检查账号密码、`DB_*` 配置与数据库是否存在。
- token 校验失败：
  - 检查请求头是否携带 Bearer token、`JWT_SECRET` 是否一致、token 是否过期。
