# 技术栈与数据模型

## 后端架构

- 运行时：Node.js 20.17+
- Web：Express 5、Helmet、CORS
- ORM：Sequelize 6
- 数据库：生产 MySQL，本地可使用 SQLite
- 鉴权：JWT，固定 issuer/audience，并通过 `tokenVersion` 支持服务端注销
- 上传：Multer 内存接收、魔数校验、UUID 文件名和用户目录隔离

入口 `src/index.js` 只负责环境校验、数据库初始化、启动与优雅关闭；`src/app.js` 负责 HTTP 中间件、路由、探针和错误处理。

## 启动与迁移

服务启动顺序如下：

1. 校验 `JWT_SECRET` 及生产环境必需变量。
2. 认证数据库连接。
3. 首次部署创建基础表。
4. 按 `SchemaMigrations` 执行未应用的版本化迁移。
5. 标记就绪并开始监听端口。

数据库或迁移失败时服务不会对外监听。发布前仍应备份数据库和上传目录，具体命令见 [数据库命令](./数据库命令.md) 与 [数据备份](./数据备份.md)。

## 核心模型

| 模型 | 作用 | 隔离边界 |
|---|---|---|
| `User` | 微信身份、资料、匹配状态、token 版本 | 用户 |
| `Couple` | 一次情侣关系及其状态、恋爱日期 | 关系 |
| `Anniversary` | 纪念日 | 创建时关系 |
| `MoodDiary` | 心情日记 | 创建时关系 |
| `MoodDiaryComment` | 日记评论 | 所属日记关系 |
| `Moment` | 情侣瞬间、图片、位置和发生时间 | 创建时关系 |
| `Menstrual` | 经期记录 | 当前有效情侣关系的两名成员；未匹配时仅创建者 |

`coupleId` 表示数据所属的历史关系。解绑会把 `Couple.status` 设为 `ended`，不会把旧记录转移给未来关系，也不会全表删除其他用户数据。

## 安全边界

### 鉴权

- `JWT_SECRET` 必须至少 32 个字符，不提供代码内回退密钥。
- token 校验 issuer、audience、用户存在性和 `tokenVersion`。
- 注销会增加 `tokenVersion`，使既有 token 立即失效。

### 数据访问

- 纪念日、心情日记和情侣瞬间查询必须匹配当前活动关系。
- 删除和修改同时校验资源关系与作者权限。
- 经期记录的所有读写只按当前用户 `userId` 查询。
- 匹配使用串行化事务和行锁，匹配码十分钟过期且一次使用后清空。

### 输入与上传

- JSON、表单和文件大小均有限制。
- 文本、日期、数组和 URL 在路由边界校验。
- 上传先鉴权再解析，图片类型由文件内容判断，目录不能由客户端控制。

## 运维

- `/health/live` 用于存活探针。
- `/health/ready` 用于就绪、发布和负载均衡探针。
- HTTP 日志包含请求 ID、方法、路径、状态码和耗时，不记录 token、session key 或请求正文。
- `UPLOAD_DIR` 必须持久化并与数据库使用一致的备份与保留策略。

