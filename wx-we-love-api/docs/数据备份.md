# 数据备份

本文档用于生产环境发版前备份数据，重点备份两类内容：

- MySQL 数据库：业务数据、用户数据、经期记录、心情日记等
- `uploads/` 上传目录：头像、图片等上传文件

发版前建议两者都备份。数据库只保存文件路径或 URL，不保存实际图片文件。

此项目使用 Docker 方式使用 MySQL 数据库。

## 1. 备份目录

建议统一放在服务器用户目录下：

```bash
mkdir -p ~/backup
cd ~/backup
```

## 2. 备份 MySQL 数据库

### 2.1 普通 MySQL 安装方式

如果服务器直接安装了 MySQL 客户端，可以执行：

```bash
mysqldump -u root -p wx_we_love > wx_we_love_$(date +%F_%H%M%S).sql
```

如果使用独立数据库用户，例如 `wx_we_love`：

```bash
mysqldump -u wx_we_love -p wx_we_love > wx_we_love_$(date +%F_%H%M%S).sql
```

执行后输入数据库密码即可。

### 2.2 Docker MySQL 方式

如果服务器没有 `mysqldump`，但 MySQL 跑在 Docker 容器里，先查看容器名：

```bash
docker ps
```

假设容器名是 `mysql-server`，执行：

```bash
docker exec -i mysql-server mysqldump -u root -p wx_we_love > ~/backup/wx_we_love_$(date +%F_%H%M%S).sql
```

执行后输入 MySQL root 密码。

### 2.3 检查备份是否有效

查看文件大小：

```bash
ls -lh ~/backup/wx_we_love_*.sql
```

正常备份文件大小应大于 `0`。如果是 `0` 字节，通常表示命令失败但 shell 重定向已经创建了空文件，这个文件不可用。

查看文件开头：

```bash
head -20 ~/backup/wx_we_love_最新时间.sql
```

正常文件开头通常类似：

```text
-- MySQL dump 10.13
-- Host: localhost    Database: wx_we_love
-- Table structure for table ...
```

空备份文件可以删除：

```bash
rm ~/backup/空文件名.sql
```

## 3. 备份上传目录

先找到 `uploads/` 目录：

```bash
find ~/repos -type d -name uploads
```

常见路径：

```text
/home/xuekai/repos/wx-we-love/wx-we-love-api/uploads
```

备份：

```bash
cd ~/backup
tar -czf uploads_$(date +%F_%H%M%S).tar.gz /home/xuekai/repos/wx-we-love/wx-we-love-api/uploads
```

如果看到：

```text
tar: Removing leading `/' from member names
```

这是正常提示，不是报错。它表示 `tar` 去掉了绝对路径开头的 `/`，避免未来解压时直接覆盖系统根目录。

检查备份文件：

```bash
ls -lh ~/backup/uploads_*.tar.gz
```

## 4. 推荐发版前检查清单

```bash
cd ~/backup
ls -lh
```

确认至少有：

```text
wx_we_love_YYYY-MM-DD_HHMMSS.sql      # MySQL 数据库备份
uploads_YYYY-MM-DD_HHMMSS.tar.gz      # 上传目录备份
```

如果本次没有任何上传文件，`uploads/` 不存在或为空，可以只备份数据库。

## 5. 恢复数据库

恢复前请谨慎确认目标数据库。恢复会覆盖或写入目标库数据。

普通 MySQL：

```bash
mysql -u root -p wx_we_love < ~/backup/wx_we_love_YYYY-MM-DD_HHMMSS.sql
```

Docker MySQL：

```bash
docker exec -i mysql-server mysql -u root -p wx_we_love < ~/backup/wx_we_love_YYYY-MM-DD_HHMMSS.sql
```

## 6. 恢复上传目录

查看压缩包内容：

```bash
tar -tzf ~/backup/uploads_YYYY-MM-DD_HHMMSS.tar.gz | head
```

解压到当前目录：

```bash
tar -xzf ~/backup/uploads_YYYY-MM-DD_HHMMSS.tar.gz
```

如果压缩包里保存的是 `home/xuekai/repos/.../uploads` 这种相对路径，解压后会在当前目录生成 `home/` 目录。可按需要把里面的 `uploads/` 拷回后端项目目录。

## 7. 本次服务器示例

本次生产环境备份示例：

```bash
cd ~/backup
docker exec -i mysql-server mysqldump -u root -p wx_we_love > ~/backup/wx_we_love_$(date +%F_%H%M%S).sql
tar -czf uploads_$(date +%F_%H%M%S).tar.gz /home/xuekai/repos/wx-we-love/wx-we-love-api/uploads
ls -lh
```

有效备份示例：

```text
wx_we_love_2026-07-07_095051.sql
uploads_2026-07-07_095506.tar.gz
```
